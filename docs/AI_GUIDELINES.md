# AI Guidelines

Version: 2.0

Status: Active

---

# Purpose

This document defines how AI assistants should contribute to Cyber Atlas.

The goal is to keep every note, diagram, component, and code contribution consistent regardless of whether it is generated by ChatGPT, Codex, or another AI assistant.

---

# Project Identity

Cyber Atlas is NOT a blog.

Cyber Atlas is NOT a note-taking application.

Cyber Atlas is an engineering knowledge graph documenting the evolution of computer science, networking, operating systems, software engineering, cloud computing, DevOps, and cybersecurity.

Every contribution should reinforce this philosophy.

---

# AI Roles

Different AI tools have different responsibilities.

## ChatGPT

Primary responsibilities

- Teaching
- Architecture
- Learning roadmap
- Markdown generation
- RFCs
- Documentation
- Diagrams
- Labs
- Practical exercises
- Project planning
- System design
- Reviewing explanations

ChatGPT should avoid generating large implementation changes without first updating project documentation.

---

## Codex

Primary responsibilities

- React implementation
- Refactoring
- Graph engine
- Markdown parsing
- UI improvements
- Search
- GitHub Actions
- Bug fixes
- Performance improvements
- TypeScript
- Tests

Codex should always read the documentation inside `/docs` before making implementation changes.

---

# Source of Truth

Priority order

```
docs/

↓

content/

↓

source code
```

If implementation conflicts with documentation,

documentation wins.

---

# Documentation Rules

Never modify project philosophy.

Never remove existing sections from Markdown notes.

Only extend them.

Every note must follow

LEARNING_TEMPLATE.md

---

# Learning Philosophy

Every topic must answer

1. Why was this invented?

2. What problem did it solve?

3. How does it work internally?

4. How is it used today?

5. How is it implemented?

6. How is it debugged?

Theory alone is not sufficient.

Every topic must include practical implementation.

---

# Graph Rules

Never manually edit graph data.

Graph must always be generated automatically from Markdown.

One Markdown file equals one graph node.

Relationships generate graph edges.

---

# Relationship Rules

Use only supported relationship types.

Do not invent new ones unless the Graph Specification is updated.

Relationship meaning should remain consistent across the project.

---

# Coding Standards

Implementation should prioritize

- readability
- maintainability
- modularity
- documentation
- accessibility
- performance

Avoid unnecessary abstractions.

---

# UI Principles

Cyber Atlas should feel like an engineering tool.

Avoid flashy animations.

Prefer clean, professional design.

Dark theme is the default.

Graph readability is more important than visual effects.

---

# Markdown Standards

Every topic follows the learning template.

Every topic contains

- Summary
- History
- Motivation
- Internal Working
- Commands
- Labs
- Debugging
- Interview Questions
- References
- Related Topics

No exceptions.

---

# Mermaid

Prefer Mermaid diagrams whenever possible.

Supported diagrams include

- Flowcharts
- Sequence diagrams
- Timelines
- State diagrams
- Architecture diagrams
- ER diagrams

Use Draw.io only when Mermaid cannot adequately represent the concept.

---

# Code Examples

Code should be

- executable
- realistic
- production-inspired
- well-commented

Avoid toy examples when a real example improves understanding.

---

# Labs

Every topic should eventually include

- Commands
- Exercises
- Debugging
- Challenge
- Expected Output

Learning ends after practical verification.

---

# Projects

Whenever applicable,

connect concepts to

- Cyber Atlas
- Vulnerability Scanner
- Future deployments

This reinforces practical learning.

---

# Future Compatibility

Every contribution should assume that Cyber Atlas will eventually support

- quizzes
- flashcards
- timelines
- progress tracking
- AI search
- recommendation engine
- prerequisite visualization
- analytics
- interactive labs

Avoid implementations that block future expansion.

---

# Before Making Changes

AI assistants should read

1. VISION.md

2. ARCHITECTURE.md

3. GRAPH_SPEC.md

4. LEARNING_TEMPLATE.md

5. STYLE_GUIDE.md

6. DECISIONS.md

before making major project modifications.

---

# Final Principle

Cyber Atlas is intended to grow over many years.

Optimize for long-term consistency instead of short-term convenience.

Every contribution should make the knowledge graph more connected, more understandable, and more useful.
